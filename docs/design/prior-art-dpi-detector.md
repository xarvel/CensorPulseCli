# Prior art: Runnin4ik/dpi-detector (разбор 2026-09-10, v4.2.4)

Python-инструмент (httpx + rich, ~7.4k строк) для РФ: проверяет чужие
домены/CDN с клиента, без своего сервера. Что у него есть и что из этого
переносится в cpprobe.

## Что делает

| Тест | Механика | Оценка |
|---|---|---|
| 0. Инфо о сети | внешний IPv4/IPv6 через ipify и др., ASN через Team Cymru по DoH, детект запущенных обходов (zapret/GoodbyeDPI/sing-box… по именам процессов) | полезно для контекста отчёта |
| 1. DNS | 13 UDP-резолверов + ~40 DoH + ~30 DoT; «правда» = DoH; UDP-ответ на запрещённый домен сравнивается с DoH; `whoami.akamai.net` показывает реальный egress-резолвер (перехват UDP/53 провайдером); заглушки провайдера = IP, повторяющийся ≥2 раз в ответах на разные запрещённые домены | сильная часть, но целиком завязана на чужие резолверы |
| 2. Домены | TLS 1.2 / TLS 1.3 / plain HTTP к списку доменов; классификация ошибок по стадии (tcp_connect / tls_handshake / reading_data) и тексту исключения | классификатор ошибок ценен, стадийная модель совпадает с нашей |
| 3. TCP 16–20KB | keep-alive к IP крупных хостингов/CDN (Hetzner, CF, Akamai, AWS, Contabo, Fastly…), 10 HEAD-запросов с `X-Pad` по 4 КБ; обрыв в окне 12–36 КБ = «DETECTED» | главная находка: сигнатура РФ-ТСПУ «рубить поток к хостингу после N КБ»; у нас такого теста нет |
| 4. Белые SNI | для «DETECTED» AS перебирает `whitelist_sni.txt` (~150 доменов Яндекс/VK/госуслуги…): с каким SNI тот же IP пропускают дальше 16 КБ | доказательство SNI-whitelist на уровне AS; переносимо на наш IP |
| 5. Telegram | TCP-пинг DC, скачивание 31 МБ, upload 10 МБ с детектом stall (10 с без данных) | throughput-модель со stall-детектом полезна |

## Чем отличается от cpprobe

- Один конец: только клиент, «правда» берётся из чужих серверов (DoH, ipify).
  Нет серверного observation, timeout ≠ drop доказать нельзя.
- Цели — реальные домены и CDN-IP, то есть измеряется доступность конкретных
  ресурсов, не политика по протоколу. Это ровно то, что мы сознательно вынесли
  за границу применимости.
- Нет UDP/QUIC/VPN-протоколов, нет фингерпринтов ClientHello (httpx = стандартный
  Python ssl).
- Хорошая эргономика: TUI, готовые бинарники, Termux/a-Shell, web-режим.

## Что взять

1. **`tcp.bulk` / throughput со stall-детектом (P1).** Наш `throughput.bounded`
   переопределить как «поток N × 4 КБ по keep-alive HTTP на наш сервер»: сервер
   отдаёт/принимает известные байты, обрыв или stall фиксируется с точным
   счётчиком байт с обеих сторон. У нас будет то, чего у них нет: серверная
   половина (сколько байт реально дошло). Пороги 12–36 КБ из их конфига.
2. **SNI-whitelist как режим `tls.sni`.** Вариант `--sni-list file`: перебор SNI
   на нашем IP с 16-КБ-нагрузкой после handshake. Различает «SNI пропускают
   handshake, но режут поток» и «SNI бел целиком». Их `whitelist_sni.txt` можно
   взять как стартовый список (MIT).
3. **Классификатор ошибок по стадиям.** Их `error_classifier` даёт хорошие
   эвристики для Python ssl (`wrong version number` → подмена ответа, EOF на
   handshake → замаскированный RST, `unrecognized_name` alert → SNI-блок). Для Go:
   разложить `tls_parse_failure` на `tls_spoof` (не-TLS байты в ответ на
   ClientHello) и `tls_alert_<desc>`; уже сейчас у нас есть `response_prefix`,
   надо только классифицировать.
4. **Заглушки провайдера.** Признак «один и тот же IP на разные заблокированные
   имена» + HTTP-ответ с этого IP. У нас DNS-тест идёт только к своему серверу,
   но это переносится на клиентскую сторону как опциональный тест системного
   резолвера (`dns.system`): запросы к нашей зоне через системный резолвер и
   сравнение с ответом напрямую; плюс `whoami`-трюк: наш сервер как
   авторитетный для зоны видит, с какого IP пришёл рекурсивный запрос, и отдаёт
   этот IP в TXT. Это даёт «кто на самом деле резолвит» без Akamai.
5. **Контекст сети в отчёте.** Внешний IP/ASN клиента и детект локального
   обхода (процессы zapret/sing-box/…) как `warnings` в report.json: скан из-под
   VPN должен быть помечен, иначе результат бессмысленен. Внешний IP у нас
   уже есть бесплатно: `client_addr` из `/v1/session`.
6. **Динамический таймаут от RTT** (3×RTT, минимум 1.5 с) вместо фиксированных
   6 с: ускоряет сканы на быстрых путях, снижает ложные таймауты на медленных.
7. **Эргономика:** готовые бинарники под все платформы (у нас есть `make cross`),
   Termux как способ запуска на Android до Этапа 3.

## Что не брать

- Списки чужих резолверов/доменов/CDN-IP как цели: расходится с моделью
  «один свой IP» и ломает анти-abuse (сервер не должен ходить наружу).
- Определение внешнего IP через сторонние сервисы: у нас его даёт control API.
- Python/httpx-стек: наш клиент должен жить в gomobile.
